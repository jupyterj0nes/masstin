# Changelog

## Unreleased

- **parse-massive reads the Linux evidence lying loose in the case folder.** It took Linux logs only out of disk images: a Linux triage dropped in the folder as a tarball (`.tar`, `.tar.gz`, `.tgz`, a UAC collection or a tar of `/etc` and `/var/log`), or an `auth.log` copied there by hand, was skipped without a word, in the terminal and when a folder is dropped on the window. The folder's tarballs and Linux logs are now found, listed (`Linux evidence found: 2 archive(s), 0 log file(s)`) and parsed with the images' Linux logs, and the Windows and Linux rows merged into the one timeline; the folder's zips stay with the Windows side, so nothing is read twice. The ingest wizard says so too: a tarball holding a Linux file system (`etc/`, `var/log/` among its first entries) is a *Linux triage* chip instead of an *other archive*, and Windows and Linux evidence side by side go to the massive pass without asking. A Linux log out of an archive that is no known triage is listed under the archive's name (`[ARCHIVE]  web01-triage.tgz`), not under the temp folder it was unpacked into; `/etc/logrotate.d/wtmp` and `btmp` (logrotate's rules) and look-alike names such as `messages.cpython-310.pyc` are no longer taken for logs: `messages` and `secure` match their rotations only (`.1`, `.2.gz`, `-20261101`). Checked on a case of a disk image, five Windows triages and two Linux tarballs: the Linux sessions, absent before, are in the timeline.
- **Viewer: a path's hop badges no longer cover the host names.** Paths and the reach cones wrote *hop 1*, *hop 2 · 01:52* in a badge right under the host, over its name (*LE[hop 1]01*). The badge now takes the side of the host the name leaves: above it, or below when the host's style puts its name above.
- **Ingest wizard: one of a kind is named in the singular.** *1 disk images*, *1 Linux triages*, *1 timelines* and *1 other archives* now read *1 disk image* and so on; the UAC chip says *UAC triage*.
- **Viewer: you choose when the account is written on the connections.** It used to vanish without a word once more than 80 connections were on screen, and came back when zooming in left fewer on screen. View › Style › Connections › *captions* now says *when not crowded* (the old rule, with the figure yours to set, 80 by default), *always* (every connection, whatever the crowd, the zoom or the overlap) or *only on hover*. A view saved with "captions only on hover" opens on hover.
- **Viewer: the time window to the second.** From and To in the filter pane (and in a window from the calendar button of the time strip): typed or pasted, or picked on a month calendar shaded by each day's events, with the hour, minute and second, the day's first and last event. The strip's handles follow. Until now the window was set only by dragging the handles, a few minutes a pixel at best.
- **Viewer: the Style window is as tall as the window allows.** Its connections and canvas sections sat under a short scroll and were easy to miss.

## v1.4.4 — 2026-11-09

- **A row taken out of a forensic image names the image, never the analyst's machine.** Since v1.4.0 the `log_filename` of such a row carried the temp folder the file sat in while masstin ran (`C:\\Users\\…\\Temp\\masstin_image_extract\\0_HRServer.e01\\evtx_extracted\\partition_0\\Security.evtx`): the rewrite that turned it into `HRServer.e01:live:Security.evtx` took the text after the last comma of the line, and the last column had become `notes`. The rows are now named before they are written (`<image>:live|vss_N:<file>`, `<image>:UAL:<mdb>`, `<image>:ntuser:<user>/NTUSER.DAT`, `<image>:tasks:<task>`, `<image>:partition_N:/var/log/<file>`), the scheduled-task rows name the image too (they said `tasks_extracted`), and the functional CI fails if a timeline parsed from a disk image carries a path of the runner.
Parsing on the machine's cores, the same timeline byte for byte; the case in a file of its own; a cinematic look for the presentation; a GIF a fraction of its size. The thread count comes from the machine (all cores but one, a single one on a small laptop) and the process runs below normal priority; the EVTX chunks, the records, several files and several images are worked at once; files of channels masstin has no parser for are left unread when their name and their records agree, a record's id is read before it is deserialised, and a log of gigabytes is read a chunk at a time. Every change was checked against the binary before it on the whole local corpus with one thread and with many, and the CI now does the same on three operating systems.

- **Parsing on the machine's cores.** The EVTX chunks are decoded on several threads (the evtx crate's own parallelism, which masstin had left at one chunk a batch), the records are turned into rows in batches spread over the pool, and the timeline is sorted and written in parallel; the rows come out the same, in the same order, since every stage collects in the order of its inputs and the sort is stable. The threads come from the machine, measured rather than assumed: the pool is all its cores but one (a single thread on one of one to three cores), and what is put to work at each moment is what is idle right then, less one core for the system, measured at the start and again as the run goes; `--threads N` or `MASSTIN_THREADS` fix it, `--threads 1` runs the serial code exactly as before. The process runs below normal priority, so the desktop comes first (`MASSTIN_PRIORITY=normal` keeps it normal on a server where masstin is the job); a file gets threads by its size, a thread every four 64 KiB chunks, so hundreds of small files do not pay for a pool they cannot use. Measured on a 12-core machine: an 8.5 MB Security.evtx decodes in 0.11 s instead of 0.42 s. The functional CI parses the public sample sets with one thread and with the machine's and compares the timelines byte for byte, on three operating systems. **Several files and several images at once**: with several threads the EVTX files are read and parsed in waves that fit a memory budget (a quarter of the free memory, half a gigabyte at least; a file over the budget goes alone), their rows kept in the files' order; `parse-image` / `parse-massive` extract images in parallel, how many found by measuring: one reader on a spinning disk or two elsewhere to start, doubled while the bytes a second coming off the images grow, back to the last size that helped when a doubling brings nothing, halved when the rate falls, the idle cores and the free memory the ceiling (`--parallel-images N` or `MASSTIN_PARALLEL_IMAGES` fix it), each image's console block held back and printed in order as its turn comes. The timeline is the same byte for byte, checked on the corpus and in the CI. **EVTX of channels masstin has no parser for are left unread** when the name is the channel's own and the records agree at six places of the file (a forwarded-events log, a renamed or archived file, a damaged chunk or a record without a channel all fail the test and are decoded whole, as before); in a typical triage that is three quarters of the bytes. `MASSTIN_SCAN_ALL_EVTX=1` decodes every file, as before. **A record's id is read from its text before it is deserialised**, and a record of an id masstin does not want is not deserialised at all (a record whose text gives no id goes the whole way); a test on real logs checks that the text and the deserialiser give the same id on every record. **An EVTX on disk is read a chunk at a time**, never loaded whole: a log of gigabytes takes no more memory than the chunks in flight; the same test checks that the disk read gives the records the memory read gives.
- `view`: **a cinematic look for the presentation and the recording**, for a client: while a hop draws the rest dims and its two hosts and line stay lit, a ping leaves the origin and a ring runs out of the destination as the line arrives (the camera never moves); the hosts reached keep a warm trace; a clock card whose time **rolls at the story's pace** while each line draws, with the pace under it (*a hop every 0.8 s*, *time ×600 · 10 min/s*) and *» faster* / *« slower* when a stretch changes it, and a jump in the timeline named (*2 days 3 h later*); the caption as a lower third sliding in, with the account in the accent, the hunt's word or the analyst's verdict as a tag, the logon under and the analyst's note on the connection; the incident's bar along the bottom with the significant hops marked; a title card before and a summary after; and the client's colour for all of it. Each piece is a switch in Record… (and the whole in the Story window); the plain look is unchanged. Autopilot: `cinematic`, `seek=SECONDS`, `record-dialog`.
- `view`: **recording a story, in one dialog, and a GIF a fraction of its size.** Record… now holds everything: the title and the logo drawn on the frames (the image, its corner, width, opacity), the format, a **quality** (small file, balanced, best), the size, the frames a second, and **where the file goes** (next to the case or the timeline, or any folder or file you pick), with **an estimate of the file's size** before recording, measured on recordings at those settings; the settings are saved with the story. The GIF was written as whole frames, each with a palette quantised at the encoder's fastest: a story of seventy connections at 720p took 350 MB, and the window waited on the encoder, so the story crawled by and Esc did nothing. A frame now stores only the pixels that changed since they were last drawn, with a palette of its own (the region's colours as they are when they fit in it, quantised otherwise), and a still frame lengthens the one before: the same story is 4.7 MB balanced (4.0 MB small, 6.4 MB best), 1.8 MB as an MP4. The MP4 is streamed into ffmpeg as the frames come, with the quality as its compression, instead of a folder of PNG frames first. **Esc stops a recording** and keeps the frames so far; the window's title counts the frames (the frames are the window itself, so nothing is drawn on them). A GIF's clock ticks in hundredths of a second, so for a GIF the dialog offers the rates that keep time: 10, 20, 25, 33, 50. Autopilot: `record=FORMAT:FPS:SIZE[:QUALITY[:FILE]]`.
- The icon: the dog's head and the network over it fill the square, the wordmark under them left out (unreadable at the taskbar's size, it kept the dog small); the window's icon and the executable's alike.
- `view`: the same graph is laid out the same way every run (the collision grid's cells were visited in a random order); the test of a held host takes the median of five starts, where one start alone could land past its bound on another machine.

- `view`: **dragging a host in a big graph.** A host is now taken where the button went down, not where the pointer is 6 points later when egui tells a drag from a click (by then, quick or over a remote desktop, it was over another host, which went instead, or over the background, which panned). While a host was held the centring waited and the graph sailed off in a block, because the springs do not pull both ends alike (300 units in a drag, 750 to 3,700 in light mode); letting go brought the centring back and everything, the dropped host too, jumped 100 to 400 points. The free hosts now share that push out among themselves while a host is held or pinned, the pulls of the held host and gravity kept (280 units of drift became 8). **A dropped host stays pinned where it was dropped**, with a pin on its corner; right-click it for Unpin, the background for **Unpin all**; pins survive a change of filter (Lay out again frees them). While a host is held the layout takes three ticks a frame, also in light mode, so the rest follows it instead of settling anew every frame. Autopilot: `pin=HOST:DX:DY`.

## v1.4.2 — 2026-11-05

The window over a remote desktop, and XFS. Over RDP or without a GPU driver the viewer draws with its own CPU rasteriser (six frames a second became twenty-nine, at half the CPU, and nothing at all with the window still); disk images with XFS and LVM volumes give their Linux logs.

- `view`: **a window that works over a remote desktop.** Over RDP, or on a Windows machine whose only display adapter is the basic one, there is no GPU: OpenGL is the generic 1.1 driver and Direct3D is WARP, the CPU emulating a GPU (155 ms a frame, six frames a second at 82 % of a two-core server, and the menu text waited for the mouse). The viewer now picks by itself **its own CPU rasteriser** there, drawn in a window loop of masstin's own: egui_software_backend's rasteriser by DGriffin91 (MIT OR Apache-2.0), brought into `src/view/soft/` and ported to egui 0.37 (std instead of no_std, the standard HashMap, egui 0.37's texture deltas, the `constify` specialisations written out), with winit, egui-winit and softbuffer around it in `src/view/softwin.rs` (screenshots for the recordings, drag and drop, clipboard, the icon, repaints asked from other threads, thirty frames a second at most). Measured over RDP on the two-core server: 29 frames a second at 43 % of the CPU while drawing every frame, 0 % with the window still. `--renderer glow` / `--renderer software` (or `MASSTIN_VIEW_RENDERER`) picks by hand. wgpu goes (it stood for WARP), and the binary is back to 30 MB. **Light mode** when drawn by the CPU or when ninety frames average under twelve a second: motion, glow, grid and spotlight off (View › Style turns them on; `MASSTIN_VIEW_LIGHT=1` asks for it), and nothing animates: the force layout settles in the first frame instead of two ticks a frame for a hundred frames (at four frames a second that was half a minute of every core after each drag, the 88 % seen in Task Manager), the camera jumps, the hover lights at once, hosts do not pop in; the window draws only when something changes. Help › About names what is drawing the window; F1 shows the real time between frames, split into masstin's part and the rendering's (it was clamped at 250 ms, which read as a cost while the window was idle). `MASSTIN_VIEW_DEBUG=1` logs frames every two seconds; the autopilot gains `size=WxH`.
- **XFS.** `parse-image` and `parse-massive` read XFS volumes, the file system RHEL, Rocky, Alma and Oracle Linux install by default: as a partition (GPT or MBR), as a bare volume image, or as an LVM logical volume, through the `rust-fs-xfs` driver faramir uses. The same logs come out as from ext4 (auth.log / secure, messages, audit.log, wtmp / btmp / lastlog, utmp, hostname, journald), through one walk shared by both file systems; a volume's kind is told by its superblock, whatever the partition type says. A test formats an XFS volume with the driver itself and takes the logs back.
- `parse-image` / `parse-massive`: **LVM** logical volumes are read in the unified image path too (they were only in the old parse-image-linux path), ext4 or XFS alike; and the copy of a logical volume no longer puts a 1 MiB buffer on the stack, which overflowed the main thread on Windows before a single volume was read.

## v1.4.0 — 2026-11-05

The graph without a database, and the evidence through the window. The timeline carries the hunt's verdict in five columns of its own; `masstin -a view` opens the lateral-movement graph in a native window (filters, neighbourhoods, paths, questions, marks, a replay that presents and records), and that window now takes the evidence too: drop it, let masstin say what it is, watch the parser's bars, open the timeline. Neo4j and Memgraph become an export.

### The hunt's verdict lives in the timeline

The timeline grows an analysis tail: five columns, empty when a parser writes them, that `graph-hunt-csv` and the analyst fill. The same five close the CSVs of caarea, faramir and allymacb, so a case tool reads one convention.

- **19 columns.** Every parse action, `parse-custom`, the Cortex readers and `merge` write `hunt`, `hunt_score`, `hunt_why`, `verdict` and `notes` after the 14 event columns ([docs/csv-format.md](docs/csv-format.md)). `hunt_score` is the q-value as a number people can read and filter: `-10 · log10(q)`, 0 to 100, so 13 is one in twenty, 30 one in a thousand, 60 one in a million; the exact q stays in `-o`. The 14 are unchanged, byte for byte, on the public EVTX-to-MITRE-Attack set and loghub's OpenSSH sample. One definition of the three layouts (`csv_out::Layout`: 12 columns of 2023, 14 until v1.3.4, 19 now) replaces the six copies of the header the readers compared against: `graph-hunt-csv` and both loaders read 14- and 19-column timelines alike (the loaders took the log file from the last column, which is now `notes`; they take it by name).
- `graph-hunt-csv`: **the timeline is annotated in place.** Every row gets the state of its connection: `significant`, `candidate` (new, tested, above alpha), `habitual` (p = 1), `not_evaluated`, `baseline` (before the cutoff) or nothing (no usable origin, origin = destination, a `CONNECT` or logon without an account, after `--end-time`), with the q-value and the explanation; a `LOGOFF` takes the state of the login it closes, by logon ID. The file is written to a temporary name and renamed over the original (retried on Windows while another program holds it). `verdict` and `notes` are kept across runs. `-o` (the table by connection) and `--report` are unchanged and now optional; `--no-annotate` keeps the old behaviour. On the public set and on Szechuan the findings and the report are byte-identical to v1.3.4 and a second run over the annotated file changes nothing.
- `merge`: reads the three layouts and writes 19 columns; when the same event comes once with its tail and once without, the tail is kept. **`--carry-marks old.csv`** (on `merge` and `graph-hunt-csv`) copies `verdict` and `notes` from an earlier timeline onto every row with the same 14 event columns, for when the evidence is parsed again.

### The graph, in masstin's own window

- **`-a view`: the lateral-movement graph without a database.** A window of masstin's own (eframe / egui, the stack agentc00pr uses) reads the timeline CSV into memory (interned hosts and accounts, adjacency per host in time order; 1 M rows take about 40 MB) and draws it the way Neo4j Browser does: a host is a circle with its name inside, cyan for a name and amber for an address the same-login test could not tie to one, a connection a line with an arrowhead and the account on it, curved when a pair has several; two hosts with more than six accounts between them become one edge that says how many. The hunt's states colour the edges (significant red, candidate orange) and ring the hosts a significant connection touches; a marked connection carries a halo. Views: **Findings** (significant + candidate), **Neighbourhood** (`--focus HOST`, or double-click; N hops), **Everything**; filters on host, user, logon type, result, hunt state, verdict and time, with `*` wildcards and `!` negation. Drag hosts, pan, zoom; the force layout (d3-style: repulsion with cell centroids beyond the neighbourhood, springs on the links, gentle gravity, no overlaps) runs while warm. The pane shows a host's connections or a connection's rows (first 300, with their event columns) and the hunt's explanation; **marks** (suspicious / confirmed / benign, notes) are written into `verdict` / `notes` of every row of the connection in the CSV, which a case tool reads as it is. The bottom bar **replays** the view in time order at a chosen speed. `--start-time` / `--end-time` bound the window. Behind the `ui` feature (on by default; `--no-default-features` builds a parser-only binary). [docs/viewer.md](docs/viewer.md).
- `view`: **presets, saved views and style.** Eleven built-in views (RDP only, network logons, SSH, admin and service accounts, without machine accounts, failures and touches, marked by the analyst, last 24 hours...), and the analyst's own, saved with their style in `<timeline>.views.json` next to the timeline. Edges coloured by result, account, logon type, hunt state or verdict, with the legend chips following; the caption on an edge chosen (account, first time, logon type, account + time, events, nothing); hosts shaped by role when asked (hexagon for a domain controller, square for a server, circle for a workstation, diamond for an external address); scales for hosts, edges and text; and **style rules**, `field + pattern -> colour, width, size, shape, dashed, glow, hide`, first match wins, with one-click rules for an account in colour, hiding machine accounts, fading the benign and hexagons for domain controllers.
- `view`: **presentation and recording.** *Present* plays the view as a story, full window: each connection draws itself from origin to destination in its turn, the host it reaches pops in, with a clock, a caption that says what happened and a counter; Space, Left / Right, Home, Esc. *Story…* edits it and saves it as `<timeline>.story.json`: rows close in time grouped into one step, the same seconds per step or the real gaps compressed and clamped, a pause on significant connections, a hold at the end, fade older, title, clock / caption / counter, anonymised names (HOST-01, user-02) for a talk, and per step its own seconds, pause, caption, skip and emphasis; **stretches** of the timeline at a speed of their own (start, end, seconds per step or minutes of the timeline a second; the first that contains a step wins), so a recording goes fast through the quiet and slow through the intrusion; and **a logo of your own** on the presentation and the recording (an image file, one of six places, width, opacity, and on the window too if wanted). *Record…* writes the story as shown, one screenshot of the window per frame at 10 to 60 fps, in the window's size or 720p / 1080p: GIF, PNG frames, or MP4 through ffmpeg when it is on the PATH; the encoder runs on its own thread as the frames arrive. `MASSTIN_VIEW_AUTO="record=gif:15:1,quit"` records and closes without a hand on the mouse.
- `view`: **a window of its own: menus, a filter pane, applied-filter chips, right-click, the hunt from the window.** A menu bar (Evidence: open, add, reload, **ingest evidence** with masstin's parsers and **merge**, as child masstins whose command line and log are shown and whose result opens in the window; Hunt; View; Tools: paths, questions, story, **open agentc00pr**, the last run's log; Help), a toolbar with icons (the three views as one control, a quick host search, fit, lay out again, motion, shapes, rules, questions, paths, **Hunt**, agentc00pr, frame budget, inspector), a **row of chips for the filters applied** (× removes one, *clear all* removes them all), a **filter pane** on the left (view, search fields, **`hunt_score ≥`**, hunt states, result, verdict, **grouping**: group accounts / one edge per account / **one edge per event**, limit, **saved filters** with the built-in presets, each keeping the filter, the style and, when asked, **the arrangement of the hosts** on the canvas, put back pinned when the filter is picked; the trash asks before deleting, one Apply button, or apply as you change them), an **inspector** on the right with Selection, Notes and Legend tabs, a status line. **Right-click** on a host (expand, only this host, paths, pin, colour, hide, note, copy), a connection (inspect, mark, note, colour / hide / only this account) and the background. **Account and host colours** picked from the legend chips or the menu, kept as style rules. **Marks ask**: a drawn edge that stands for several rows is marked on the whole block or on the rows ticked. **Notes** on a host, a connection or the case go to `<timeline>.notes.json`. The **time strip is the time filter**: two handles narrow the window (From / To, chips and fields follow), double-click frees it, the replay head is separate. The **replay** advances by rows a second or **by the clock** (a minute to a week of the timeline a second), and each connection it reaches **draws itself** from origin to destination over a chosen time, the host popping in when the line arrives. **The hunt runs from the window** (`graph-hunt-csv` as a child, start prefilled from the window, alpha, end; a sweep while it runs; on its end the findings light up one after another, each with a flash, and the score slider takes over). The look is the viewer's own: Inter and Phosphor icons embedded (OFL and MIT, `src/view/fonts/`), rounded controls, pills, one accent. `MASSTIN_VIEW_AUTO` gains `hunt=<start>`.
- `view`: **a picture that holds up with thousands of hosts, and a look to match.** The force layout is d3's in full: repulsion through a Barnes-Hut quadtree (`n log n`; a tick over 3,000 hosts and 47,000 links costs about 8 ms where the cell-centroid version took seconds), springs weakened on busy hosts (1 / the smaller degree, so a hub's leaves no longer crush it into a ball), the picture recentred every tick (the springs do not conserve momentum; a graph with hubs used to sail off the screen), overlaps resolved on a hash grid the size of a host and for three seconds after the forces cool, a time budget per frame. Per-edge and per-host looks (rules, colours, the fan of parallel curves, the adjacency) are resolved once per query and style instead of every frame; the legend chips too. Beyond 2,500 edges on screen the unlit edges go into one mesh as straight segments (findings keep their colour), small hosts into one mesh as feathered discs, captions and halos are dropped, and the detail comes back on zoom. Measured: 600 hosts and 12,700 edges at 48 frames a second settled, 40 while the layout runs; 3,000 hosts with 47,000 edges at 29 settled and 20 while the layout runs; the 15 hosts of a lab at the display's rate. **F1** (or `MASSTIN_VIEW_HUD=1`) shows the frame budget. The look: a deep canvas with a soft spotlight and a dot grid that pans and zooms with the camera; hosts as glossy orbs with a highlight and a bright rim; edges with a gradient from a dim origin to a bright destination and a sleeker arrowhead; the findings glow, a significant host breathes, a hovered host gets a pulsing ring; bright dots travel along the connections that matter (**motion**, a checkbox saved with the style; off for a still picture); hover and selection fade the rest out smoothly; a host entering the view pops in; the camera glides to Fit, zoom and neighbourhoods; captions in pills, never on top of one another; chips as outlined pills. The replay bar's slider is now a **histogram of the view's events over time** (log scale, red where a significant connection falls, bright up to the cursor), click or drag to scrub, hover for the time. For scripts and tests `MASSTIN_VIEW_AUTO` gains `shot=file.png`, `all=LIMIT`, `select=HOST`, `zoom=F`, `hud`, `motion`, `bench=N[:cold]` and `wait=SECONDS`.
- `view`: **three looks, and a lighter picture.** The hosts are drawn in a **mode**: *realistic* (the machines shaded, with a shadow and their lights), *icons* (clean tiles with a glyph for what the host is, like a network diagram) or *arcade* (a video game: the machines as 16 × 16 pixel sprites with blinking lights, names in Press Start 2P (OFL, embedded), a starfield with parallax, scanlines, square bullets along the connections), besides glass and minimal. Motion adds motes drifting over the canvas, and every line carries a faint halo. ## v1.1.0 — 2026-10-05

### The statistical graph-hunt

`graph-hunt` is no longer a scorer with hand-picked weights: every signal is a probability measured against the network's own baseline, and `--alpha` is the only number you choose. The same hunt runs on Neo4j, on Memgraph and straight from the timeline CSV (`graph-hunt-csv`), with Hopper's classes, causal paths, `--seed` reconstruction and an analyst `--report`. On the public Los Alamos set (21 M rows) the first 100 rows are 99 % red team and an incident-free period yields nothing. Around it: Linux session ends and `logon_id`, UAC triages, Sysmon Event 3, a JSON extractor for custom rules, images inside zips for `parse-massive`, and a long list of parser fixes validated on real EVTX.

- `parse-windows` / `parser-elastic` / `parse-cortex-evtx-forensics`: **4778 and 4779 carry logon_type 10.** Session reconnect / disconnect are Terminal Services events; the column was empty (Cortex gave them 3). Validated on the EVTX-to-MITRE-Attack samples.
- `parse-custom`: **`type: json` extractor**. A rule can now parse NDJSON logs (one JSON object per line) and pull scalar fields by dot-path, both flat (`EventID`, `TargetUserName`, `SourceIp` — the Mordor / nxlog / HELK / SIEM-export shape) and nested (`winlog.event_id`). This closes the JSON gap in the custom-parser framework and lets masstin ingest JSON event logs it could not before. Ships with a new library rule **`rules/json/mordor.yaml`** for the OTRF Security-Datasets (Sysmon Event 3 on lateral-movement ports, 4624/4625/4634/4647/4648/5140); validated end-to-end against real OTRF data.
- `parse-windows` / `parse-image` / `parse-massive`: **Sysmon Operational Event ID 3 (network connection)** is now parsed (Sysmon EVTX was ignored entirely before). The host running Sysmon is the local endpoint; `Initiated` decides direction (outbound local -> remote on the destination port, inbound remote -> local on the source port). Only connections whose service port is a lateral-movement one (22, 135, 139, 445, 1433, 3306, 3389, 5900, 5985, 5986) are kept — Sysmon logs every connection, so the port filter keeps the volume sane — and each becomes a `CONNECT` edge origin -> destination with the initiating process and protocol in `detail`. - `parse-massive`: **forensic images packed inside a zip** (E01 multi-segment, VMDK with its extents, dd/raw/img) are now processed. A pre-flight free-space check skips an archive instead of filling the disk half-way.
- `parse-linux`: **syslog lines with ISO timestamps** (`2026-09-25T10:11:12.123456+02:00 host sshd[1]: ...`, rsyslog's `RSYSLOG_FileFormat`, the Debian 13 default) are parsed; they were dropped. The stamp's own offset is used, whole seconds kept.

- `parse-linux`: **December lines in the current, unrotated `secure` / `auth.log`** get the previous year: a line cannot be dated after the file was last written (same rule as the logrotate suffix, with a day of slack). They were stamped with the following year and sorted into the future.

- `load-neo4j` / `load-memgraph`: **CSV fields are read with quotes honoured.** The loaders split every line on raw commas, so an account name or detail text containing a comma (which an attacker can choose) shifted the columns and could put a chosen value in the origin of an edge; `graph-hunt-csv` already read quotes. A comma inside a field becomes `_`.

The explanation names the home: "the account belongs elsewhere: 100% of its earlier login-days came from C8198 (7 day(s))". No inventory needed.

The previous rule, "the past with the window's gap", needed a baseline longer than the window and on LANL (7 baseline days, 9 window days) left no null at all. - `graph-hunt` / `graph-hunt-neo4j`: **`--sigma` corroboration with Hayabusa / Chainsaw.** Their JSON or JSONL output (files or directories, comma-separated) is read once; a hit on a machine while a login session is open on it (from the login to its LOGOFF, or the end of the day) is the coordinate `sigma` (distinct rules that fired) of that connection, measured against the baseline like every other, and the explanation names the rules, times and levels. masstin does not detect PsExec, WMI or service installs itself; it joins what those tools found to the login that made it possible.
- `graph-hunt` / `graph-hunt-neo4j`: **`--seed` reconstruction.** Given known-bad hosts, IPs or accounts (comma-separated), the report opens with the chain: every window login by a seed, then every login leaving the entered machine while that session is open (LOGOFF when recorded, else the end of the UTC day) that is a new connection or uses an account the chain already used, with certainty 1 / (sessions open on the machine at that moment); one level back (what was open on a seed machine when it first acted); failed attempts and unauthenticated touches from the chain machines; and two Cypher queries: the chain as a virtual graph (APOC; real-edge match on Memgraph) and everything between the chain machines in that time span. Requires `--report`. A seed that existed in the baseline starts the chain only with its new connections (its habitual logins are counted and listed, not followed); a never-seen seed with everything. `host:account` seeds both at once; `--seed-from` / `--seed-to` bound the logins that start the chain.

- **`graph-hunt` / `graph-hunt-neo4j`: Hopper's signature, causal paths, analyst report** ([design](docs/graph-hunt-statistics.md)).
  - each connection is classed by the two properties Hopper (Ho et al., USENIX Security 2021) found in lateral movement: a **credential switch** (account owned by other origins, never used by this one) and a **new access** (destination new for the origin or the account). The class is the first clause of `why_unusual` and orders the rows within the significant set; p-values are untouched. New origin-day coordinate `credential-switch`.
  - `chain-motif` replaced by **`causal-path`**: a login B→C is caused by one of the logins A→B of the same UTC day, with certainty 1 / #candidates; the path counts when the credential changed at B and the causal account had never reached C. The connection row explains the path in words.

  - **`--report path.md`**: one story per origin with a significant connection: baseline presence, chronological phases, reasons with baseline counts, account owners, causal paths, campaign, log families, Browser query.

  - **Statistical review fixes** ([assumptions and limits](docs/graph-hunt-statistics.md#assumptions-limits-and-what-the-numbers-mean)): past-only reference with the window's gap (a fact is new on the first day it appears, for baseline and window days alike; the former leave-one-day-out made a repeating fact never new in the baseline and new on every window day); the Benjamini-Hochberg family holds the new connections only (habitual ones have p = 1 and cost no power); the run prints the smallest reachable p; an empty null gives p = 1 instead of a crash; account names with non-ASCII characters no longer crash the uid check; a refused attempt is not a "use" of an account by an origin (a spray that started before the cutoff and succeeds in the window is a credential switch); origins without history are judged with every destination-side fact switched off on uncovered destinations; PageRank iterated to stationarity with a data-derived zero threshold; the causal-path coordinate counts connections, not sessions; the panel ends on the last covered baseline day and an empty panel stops the run; an IP and its own unresolved host name are never paired as a campaign; explanations state on how many baseline days each fact occurred.
  - **IP ↔ host name resolution is a binomial test** over the IP's logins (trials) and the seconds where exactly that name was recorded too (votes), with the name's own rate as chance probability; BH across (IP, name) candidates, one unambiguous name per IP. The former product of per-vote probabilities was a likelihood, not a tail probability, and could fold two busy machines sharing an account.
- **`graph-hunt` / `graph-hunt-neo4j` rewritten as a statistical engine** ([design](docs/graph-hunt-statistics.md)). Every hand-picked weight, window, minimum and threshold is gone; each signal is an empirical probability measured against the network's own baseline, and `--alpha` (false discovery rate, default 0.05) is the only chosen number.

### What's in 1.0

**Windows parsing**

- `parse-windows`: EVTX from directories, files, and recursive zip trees. Dispatch by `Provider.Name`, so archived and renamed logs (`Security-YYYY-MM-DD-HH-MM-SS.evtx`, operator-renamed copies, third-party triage extracts) all parse correctly.
- `parse-image`: forensic disk images (E01, VMDK in every variant, raw/dd, img) with per-partition OS auto-detection, NTFS walker, VSS recovery, UAL, Scheduled Tasks, MountPoints2.
- `parse-massive`: everything above plus KAPE / Velociraptor / Cortex XDR triage detection and loose-artifact promotion. One command for mixed evidence piles.
- `carve-image`: Tier 1 chunk recovery + Tier 2 orphan record detection from unallocated space, hardened against the upstream `evtx` crate's pathological BinXML allocations via subprocess isolation.

**Linux parsing**

- `parse-linux`: auth.log, secure, messages, audit.log, utmp, wtmp, btmp, lastlog.
- `parse-image` on ext4: the same plus a pure-Rust systemd-journald binary log reader, for modern systems where the text logs are empty and all authentication events live in the journal.

**Third-party integrations**

- `parse-cortex` and `parse-cortex-evtx-forensics`: Cortex XDR API queries for network connections and forensic EVTX collections.
- `parser-elastic`: Winlogbeat JSON dumps exported from Elasticsearch.
- `parse-custom`: any VPN / firewall / proxy / web app log via YAML rule files. Ships with 8 pre-built rules for Palo Alto GlobalProtect, Cisco AnyConnect, Fortinet SSL-VPN, OpenVPN, Palo Alto traffic logs, Cisco ASA, Fortinet FortiGate, and Squid.

**Graph output**

- `load-neo4j` / `load-memgraph`: grouped (topology) or ungrouped (temporal path hunting) loading modes.
- `merge-neo4j-nodes` / `merge-memgraph-nodes`: vanilla Cypher node fusion, no APOC / MAGE required.

**Binaries**

Zero runtime dependencies on every platform:

- Windows x86_64
- Linux x86_64
- macOS Apple Silicon (arm64) — native
- macOS Intel (x86_64) — native

**Filtering**

`--ignore-local`, `--exclude-users`, `--exclude-hosts`, `--exclude-ips` (CIDR and `@file.txt` syntax) for cutting noise out of long timelines.
