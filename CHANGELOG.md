# Changelog

## Unreleased

- `parse-windows` / `parse-image` / `parse-massive` / `parser-elastic`: **a logoff carries the origin of the logon it closes.** 4634 and 4647 name no source machine, so every Windows LOGOFF row had none (2,277 rows on the DFIR Madness Szechuan case) and graph-hunt and the loaders discarded them. Each now takes the origin, and the logon type when it has none (4647), of the 4624 with the same logon ID on the same machine, the latest one at or before it, as parse-linux pairs a session end with its login by sshd pid. A logoff whose logon is not in the evidence names no origin and is not written (a masstin row needs an origin and a destination); the run prints how many were paired and how many dropped. On Szechuan 2,299 of 2,300 are paired. Other rows are unchanged on the public EVTX sets.
- `graph-hunt` / `graph-hunt-neo4j` / `graph-hunt-csv`: **the same timeline gives the same output on every run.** When two logon types were equally rare on a destination, the explanation named whichever a hash map listed first, which changed from run to run (1 run in 4 on Szechuan wrote "logon type 3 is rare" instead of "logon type 10"). Ties are now broken by name; ten runs give byte-identical CSV and report. The functional CI runs the hunt three times on every operating system and requires identical output.

## v1.3.2 — 2026-10-08

### A loaded graph holds every edge

`load-memgraph` lost edges without saying so: a time with 7 digits of a second (every EVTX time) made its whole batch fail, and on the public EVTX samples the graph held 225 of the 787 edges the loader reported. Both loaders now count what the database created and report a failed batch. The loaders also decide machine identity on the same corpus as graph-hunt, so a hunt on a loaded Neo4j or Memgraph graph gives the same output as `graph-hunt-csv`, which the functional CI now checks against real Neo4j and Memgraph instances on every push. Carving VMDK, VHD/VHDX and raw images gets the decoder timeout E01 had.

- `load-memgraph`: **no more silently lost edges.** Memgraph's `localDateTime()` takes 0, 3 or 6 digits of a second; EVTX times carry 7 (and other sources 9), and one such value made its whole batch of edges fail, while the loader reported every edge as loaded: on the public EVTX samples 562 of 787 edges (the two largest accounts) were missing from the graph. Times are now cut to 6 digits for Memgraph, and both loaders count what the server says it created; a batch that fails is reported (an error raised while the result was read used to be counted as success, in the Neo4j loader too).
- `load-neo4j` / `load-memgraph`: **the same machines as graph-hunt-csv.** The loaders ran the same-login test on the rows with a single source side only, which under-counted each name's login rate and folded IPs graph-hunt does not (on the public EVTX samples, `10.23.123.11` into `ATTACKER`). They now run it on the corpus graph-hunt builds from the same file.
- `graph-hunt` / `graph-hunt-neo4j` / `graph-hunt-csv`: rows that tie on every ranking key are ordered by origin, destination, account, result and day, so the output does not depend on the order the rows arrived in. With the two fixes above, the three hunts give byte-identical output on the public EVTX samples (cypher_snippet aside), which the functional CI now checks.
- `carve-image`: **a chunk that hangs the EVTX decoder no longer hangs the carve on VMDK, VHD/VHDX and raw images.** The provider check of each candidate chunk ran with a 3-second budget on E01 only; the other image formats caught panics but not an endless loop in the decoder. Both paths now share the timed check; a hung chunk is reported and skipped. Same rows as before on a raw image of the public EVTX samples (266).
- `merge-neo4j-nodes` reads the password from `$NEO4J_PASSWORD`, as `load-neo4j` and `graph-hunt-neo4j` do (it only prompted).
- **CI:** the functional workflow loads the public EVTX timeline into Neo4j and Memgraph (service containers), requires the same node and edge counts from both loaders, the same hunt from `graph-hunt-csv`, `graph-hunt-neo4j` and `graph-hunt`, and that both node merges move every edge and remove the old node. Those actions ran in no workflow before.

## v1.3.1 — 2026-10-08

### The same row from every carrier

A Windows event now gives the same row whether masstin reads it from an EVTX, from a Winlogbeat or Elastic Agent export, or from Cortex XDR. The Winlogbeat reader had its own copy of every event mapping and had drifted from parse-windows (missing accounts and origins, reversed edges, DNS queries taken for RDP reconnections); it now goes through the parse-windows mapping of each event's channel. The Cortex forensics query asked for events its own filter then dropped; it now extracts them. Every custom rule writes a time the rest of masstin reads, Cisco rows get a time and a destination, and rows without an origin or a destination are counted instead of written. One TLS stack, no OpenSSL on Linux, and parse-linux is tested on a real OpenSSH log on every push.

- `parse-custom`: **every rule writes a time the rest of masstin reads, and Cisco rows have one.** The Cisco ASA and AnyConnect rules (10 parsers) mapped `time_created` and most destinations to empty values: their rows had no time and no destination. They now read the syslog header (`<PRI>Apr 13 10:15:23 asa-lab01 : %ASA-...`, also with the year that `logging timestamp` adds), the ASA as destination where the event names no other. A syslog stamp without a year (Cisco, OpenVPN wrote `Apr 13 09:14:22` as it came) takes the year from the file (logrotate suffix, or the day after it was last written; December lines in a January file are the year before), as parse-linux does. Palo Alto's `2026/04/13 09:15:18` and Squid's `1744530015.123` are rewritten as ISO too, and the readers of a timeline accept those two shapes. A matched line whose mapping leaves the origin or the destination empty is no longer written: the summary counts it (`Not written`), since a masstin row needs both. Lines are read with the evidence reader (bad bytes kept, read errors reported) instead of being skipped silently.
- `parser-elastic`: **the same row as `parse-windows` for the same event.** The Winlogbeat reader had its own copy of every event mapping and it had drifted: 4778/4779 and 4776 were read with the 4624 field names, so a session reconnect or an NTLM validation came out with no account and no origin (checked on Elastic's own Winlogbeat fixtures: `at_adm` from `EQP01777` / `10.100.150.9` became a row with neither); 4648, 31001 and 1024, written on the source machine, came out with the edge reversed; 5140 lost its user; WinRM 6, WMI 5858 and Sysmon 3 were not read; UserData events (1149, 21-25, 551/1009) were read from `event_data`. Events were also picked by id alone, and ids repeat across channels: on Elastic's Sysmon fixtures the old reader turned 157 DNS queries (Sysmon 22) into RDP reconnections and Sysmon 24/25 into RDP logoff / logon. Now each document is reduced to the event and its fields and goes through the parse-windows mapping of its channel (`winlog.channel`; by id only for the ids unique to one family when a document has no channel). `winlog.computer_name` is the destination (`host.name` is the shipper, the collector under Windows Event Forwarding). Documents from Elastic Agent's Windows integration (`agent.type` is not `winlogbeat`) and documents without `@timestamp` (`winlog.time_created`) are read. parse-windows output is unchanged (the mapping was moved, not changed: byte-identical on both public EVTX sets and the local validation set).
- `parse-cortex-evtx-forensics`: **the XQL query covers what it asked for.** It requested the parse-windows event ids but dropped most of them: Kerberos 4768-4771 had no destination, 4778/4779 no origin, 1024 no destination, WinRM 6 no origin, so the query's own filter removed them all; the SubStatus of 4625 was never extracted (an earlier branch of the same `if` caught 4625); the SmbClient/Connectivity channel was not queried; 1149 lost its user (the message prints `User:` and `Domain:` on separate lines, not `DOMAIN\user`); an empty `Workstation Name:` or `Process Name:` took the next line's label as its value (4624 with origin `Source`). Fixed, plus: Kerberos and NTLM failures follow their result / error code as in parse-windows, `::ffff:` and IPv6 sources are kept whole, a host name in the address column moves to `src_computer`, WMI 5858 from the machine itself or a service account is dropped as in parse-windows, `event_id` is read as a number or a string, and a 1149 whose domain was empty (Windows then renders `Domain: <address>` and `Source Network Address: %3`) keeps its address. Checked by evaluating the query's expressions on the real rendered messages of the public EVTX sets: Kerberos 0 -> 84 / 44 / 80 rows, 4778/4779 0 -> 3, 1149 10 -> 21 of 22; not run against a live tenant.
- **Build:** one TLS stack. `reqwest` (the Cortex XDR client) uses rustls with the operating system's root certificates, like the graph database driver, instead of OpenSSL / SChannel: the Linux build no longer needs OpenSSL, and a corporate CA installed in the system store is still trusted. Not yet exercised against a live Cortex tenant.
- **Build:** `serde_yaml` (deprecated upstream) replaced by its maintained fork `serde_yaml_ng` for the custom rules; the 13 rules give byte-identical output on their samples. The unused `mbrman` dependency is gone. `notatin` accepts any `nom` from 6 up but builds only with 7; the lockfile pins it and the builds use `--locked`.
- **CI:** the functional workflow runs `parse-linux` on a public OpenSSH log (loghub OpenSSH_2k) on the three operating systems, requires the same timeline from each, and checks that the same log as a `.gz` cut in half ends with a warning and the rows before the cut. `filter.rs` has unit tests. The manual macOS debug shell no longer asks for the retired paid Intel runner: the Intel binary is built on Apple Silicon and runs under Rosetta.

## v1.3.0 — 2026-10-08

### macOS, and evidence that is damaged

masstin now reads macOS: the Unified Log, straight from a `.logarchive` acquired from the Mac or from a `log show` export, on any operating system, with SSH and Screen Sharing logons validated on real Sonoma and Sequoia logs. Disk images can be VHD and VHDX, four vendors join the custom-rule library, and timestamps from every rule come out in one format. A damaged file no longer stops a case: a truncated rotated log, an odd byte in a line or a corrupt image header is reported and the run goes on with everything that could be read. `--db` reaches every graph action, and the documentation now says what the code does.

- **Damaged evidence no longer hangs or crashes a run.** A truncated or corrupt rotated log (`auth.log.2.gz` copied half-way, a common triage leftover) made `parse-linux` spin forever at full CPU with no output; it now keeps every line read before the damage and says where the read stopped (`auth.log.1.gz: read stopped after 9918 line(s): corrupt deflate stream`). A line with bytes that are not UTF-8 (an SSH user name is chosen by whoever connects) was dropped silently; it is now kept with the bad bytes as U+FFFD and counted in a warning. Same reader for Winlogbeat exports and `log show` exports (`parse-mac` stopped at the first bad byte of an ndjson and dropped a whole `--style json` file). Panics removed: an audit record with an out-of-range time (`msg=audit(inf:1)`), a dmesg `Set hostname to <>`, an evidence log that cannot be opened (permissions, a file gone since the scan), a WMI 5858 operation with non-ASCII text longer than 100 bytes (`parse-windows`), a sparse VMDK header with `numGTEsPerGT = 0` (division by zero) and VMDK / VHD / VHDX headers whose sizes asked for terabytes of memory, which are now refused as damaged. A `ZERO` extent in a VMDK descriptor reads zeros without a backing file (it opened `/dev/null`, which does not exist on Windows). The dmesg hostname also lost its first character. Output on intact evidence is byte-identical (EVTX samples, a Linux tree with plain, CRLF, ISO and gzip logs and audit, Winlogbeat, macOS export).
- **`--db` reaches every graph action.** `load-memgraph`, `merge-memgraph-nodes` and `graph-hunt` always used the database `memgraph` and `merge-neo4j-nodes` the server default, whatever `--db` said; only `load-neo4j` and `graph-hunt-neo4j` honoured it. Defaults unchanged (`neo4j` / `memgraph`).
- `parse-windows`: **a renamed or archived SMB Client Connectivity log keeps its 30803-30808 events.** Logs whose file name is not the stock one are routed by provider; the Connectivity channel shares the `Microsoft-Windows-SMBClient` provider with the Security channel and was read for 31001 only (its fallback arm was keyed by a file name, which never matches a provider). Not yet checked on a real renamed log with those events: the public sample found holds only 30810-30813.
- `parse-custom` without `-o` writes the timeline to stdout, as every other parser does; it wrote nothing.
- `--stdout` is hidden: it never did anything (output goes to stdout whenever `-o` is omitted) and is still accepted so existing command lines parse. `--carve-unalloc` says it is not implemented yet instead of announcing an unallocated-only scan; the whole image is scanned, as before.
- **Docs follow the code.** The CLI reference lists the action aliases, what `-f` takes per action, the `https://api-` form of `--cortex-url`, the real Cortex defaults in `--help`, and `--end-time` / `--user` for every action that reads them. parsing.md lists the 13 custom rules and xinetd `SSH_CONNECT`, marks UAL and triage detection for `parse-windows`, and states what Winlogbeat and Cortex forensics do not cover yet instead of claiming parity with `parse-windows`. custom-parsers.md documents the four extractors and the real rejected-lines behaviour. The graph-hunt pages describe the test the engine runs: one conformal p-value per new connection and Benjamini-Hochberg across connections (no per-origin-day Simes step), a past-only reference, the panel start day maximising min(login panel, failure panel) x null days, three flavours, LANL days 0 to 15, and the measured coordinates instead of a timing-based chain speed that no longer exists.
- `parser-elastic`: **`winlog.event_id` read as a number or a string.** Winlogbeat 8 writes it as a string; such an export gave no rows at all.
- **`parse-mac`: a macOS parser.** Reads the Unified Log — a `.logarchive` bundle (binary `tracev3`, read directly with the pure-Rust `macos-unifiedlogs` crate, so an archive acquired from a Mac is parsed on Windows or Linux too) or a `log show --style ndjson` / `json` export (dependency-free, resolved off the host). Extracts the two confirmed macOS remote-access vectors: SSH (`sshd` / `sshd-session` — success, failure, `invalid user` and policy denials, pre-auth contact, disconnect; the OpenSSH text is the same masstin reads on Linux) and Screen Sharing / Apple Remote Desktop (`screensharingd` — `Authentication: SUCCEEDED/FAILED :: User Name: … :: Viewer Address: …`). Console logins, `sudo` and `su` are host-local and dropped; the CSV stays the 14-column lateral-movement timeline. Validated end-to-end on a real public `.logarchive` (Mandiant High Sierra test set) and on synthetic `log show` exports; classification unit-tested on the real message text. `smbd`, `system.log` / ASL text, the utmpx / wtmpx databases and APFS images are the documented next step.
- `parse-mac`: **validated on real Sonoma 14.8 and Sequoia 15.7 Unified Logs.** A manual workflow (`mac-evidence.yml`) makes SSH logons against a GitHub macOS runner (key login, wrong password, non-existent user, port probe, bad banner, disconnect), collects that span with `log collect` and `log show --info`, and runs parse-mac on the bundle and on both export styles. The sshd `Accepted` / `Failed` / `Disconnected` lines are persisted on both versions, written by `sshd-session` (OpenSSH 9.9), and parse-mac reads them from the binary bundle on Windows exactly as on the Mac (same 8 rows from the bundle and from the export). An SSH password login (`Accepted password`) is covered too. Screen Sharing: on both versions a real ARD / VNC authentication was made and the `Authentication: SUCCEEDED/FAILED :: User Name: ... :: Viewer Address: ...` line of older macOS is not written any more (the format string is absent from screensharingd); what is persisted is `*outUID= <uid>` + `authResult = 0/1` without the account name and, on Sequoia failures only, `new viewer connection: <ip>`. parse-mac now pairs those lines per process within 5 s: a viewer address with `authResult = 0` is a `SUCCESSFUL_LOGON` with the account as `uid:<n>` (the parse-linux convention for auditd), with `authResult = 1` a `FAILED_LOGON`, with no outcome a `CONNECT`; an outcome without an address makes no row (a masstin row needs an origin) and is counted by `--debug`. On the Sequoia bundle that is two refused attempts with their address; on Sonoma nothing, as the address is not written. Unified Log timestamps are truncated to the microsecond as `log show` prints them, so a bundle and its export give the same rows (the crate hands the instant over as a float, so one row in twenty-odd can still differ by a microsecond). Two pre-auth shapes macOS writes without the `[preauth]` tag Linux uses are now recognised: a bare `Connection closed by <ip> port <n>` and `banner exchange: Connection from <ip> port <n>: invalid format`. The bundles are workflow artifacts, kept as fixtures outside the repo.
- `parse-mac`: **the noise filters apply** (`--ignore-local`, `--exclude-users`, `--exclude-hosts`, `--exclude-ips`, `--dry-run`); they were skipped on this parser alone. A `log show --style ndjson` export is read line by line (a few weeks of `log show` are several GB); a `.json` file is taken for a `log show` export only when it carries `eventMessage`, so other JSON lying in a triage tree (Velociraptor results) is left alone. `--debug` prints, per `.logarchive`, how many records were scanned, how many came from sshd / screensharingd and how many became rows, with the sshd / screensharingd messages that classified as nothing, so an empty timeline can be explained. Verified on the six Mandiant test bundles (High Sierra to Tahoe, up to 4.3 M records, 327 MB peak): none holds a persisted SSH or Screen Sharing logon text, which is what an empty timeline means there.
- `parse-custom`: **four new rules, 13 parsers** — Check Point Log Exporter syslog (remote access / Mobile Access session login, failure and logout; administrator logins to the management, failures and Expert Shell SSH logins), Zscaler ZPA LSS JSON (device session authenticated / failed / disconnected, application connections) and Cloudflare Access Logpush `access_requests` (login allowed / denied, logout). Validated on the public test fixtures of the Elastic integrations repository, kept under `rules/*/samples/`. Library: 13 rules, 50 parsers.
- `parse-custom`: **`${a|b}` in the map** takes the first alternative with a value (Check Point names the account `user` on some records and `src_user_name` on others; ZPA activity rows carry `Host` or only `ServerIP`).
- `parse-custom`: key=value values lose the padding some vendors keep inside the quotes (Check Point writes `user:" Jane Doe "`).
- **Timestamps:** `parse-custom` rewrites C asctime (`Fri May 31 17:35:42 2019`, what Zscaler writes) and Unix epochs in seconds, milliseconds, microseconds or nanoseconds (what Cloudflare Logpush writes when configured so) as ISO UTC, so the CSV stays homogeneous; ISO values are written as they come. Every reader of `time_created` (loaders, graph-hunt, `merge`, the parsers' own sort) also accepts those two shapes, for timelines written before this change.
- `parse-image` / `parse-massive` / `carve-image`: **VHD and VHDX images** (Hyper-V, Azure, Windows Backup): fixed and dynamic in both formats, read through the same walkers as E01 and VMDK (`src/vhd.rs`). Differencing disks with a parent are refused with a message instead of silently reading holes. Validated on disks created by diskpart with the public EVTX samples inside (fixed and dynamic VHD, fixed and dynamic VHDX): same 848 rows as the loose files; the functional CI now builds a dynamic VHD and a dynamic VHDX on the Windows runner and parses the VHD on Linux and macOS too.
- **CI:** the functional workflow now exercises `parse-image` on the three operating systems. The Windows runner builds a raw NTFS disk image with diskpart (a fixed VHD formatted by Windows, the public EVTX samples copied under `Windows\System32\winevt\Logs`, the 512-byte VHD footer stripped), parses it, and hands it to the Linux and macOS runners as an artifact; the compare job requires the same timeline from every OS and the same events from the image as from the loose files. No multi-GB download: public Windows 10 images weigh tens of GB and the small public ones are XP with `.evt` logs.

## v1.2.0 — 2026-10-07

### One rule of identity, and a build that is tested where it ships

The loaders and the hunt now agree on what a machine is: an IP is folded into a host name only when the same-login test says so, and a hunt on a loaded graph gives the same rows, labels and p-values as a hunt on the CSV. The campaign test is calibrated against the shared account's own footprint instead of the whole panel. The SMB parsers were checked against records generated on a live Windows host and fixed. Under the hood, polars is gone and quick-xml is current, and every push now builds and runs the whole pipeline on real event logs on Linux, Windows and macOS (Apple Silicon natively, Intel under Rosetta) before anything is tagged.

- `graph-hunt` / `graph-hunt-neo4j` / `graph-hunt-csv`: **the campaign test draws from the shared account's own footprint**, not from the whole panel. Two origins with no history that share a new account were tested for destination overlap as if each had picked its destinations from every panel host, so two newcomers using the same account (a person's two machines, a service account from two new hosts) always "overlapped beyond chance": on LANL 172,719 of 180,707 candidate pairs were called campaigns. The population is now the destinations that account reached in the window from any origin; a pair is annotated only when the two overlap more than two independent users of the account would. Unit test with both cases; the summary line reads "... overlap beyond the account's own footprint".
- `parse-windows`: **SMB and WMI parsers validated on records generated on a live Windows 11 host** (the public EVTX sample sets contain none of them). Fixed what that showed: SMBServer 551/1009 write `ClientName` as a UNC reference (`\192.0.2.76`), which landed in `src_computer` with its backslashes and was never recognised as an address; it is now stripped, `src_ip` carries the address, the `ClientAddress` socket dump is decoded when the name is empty, `UserName` is split into user and domain (`NT AUTHORITY\ANONYMOUS LOGON`) and the NT status goes to `detail` (`Status 0xc000006d`). SmbClient 31001 and 3080x (written on the client) put the local computer name in **both** `src_computer` and `src_ip`; now a name goes to `src_computer` only, `ServerName` loses its leading backslashes, and the share that 30807 appends to the server name (`\192.0.2.31\C$`) goes to `detail` instead of the destination. WinRM 6 verified unchanged (direction and destination correct on ten records). WMI 5858 is now a record-level function with unit tests on a real record (remote client kept, local client and service accounts dropped); the live host only had local clients to offer. 31001 itself could not be produced on the host (its client logged 31017), the fix is by construction.
- `load-neo4j` / `load-memgraph`: **one rule of machine identity.** An IP is folded into a hostname node only when the same-login co-occurrence test accepts that name (binomial against chance coincidences, Benjamini-Hochberg across candidates, one unambiguous name per IP), the rule `graph-hunt` already applied; the host node lists the folded IPs in `aliases` with `alias_votes` and `alias_p` (the former `resolved_name` annotation on IP nodes is gone with the nodes). The frequency map of (src_ip, src_computer) pairs with its x1000 (4778/4779) and x100 (machine account) weights is gone: it took the most frequent name, so a renamed machine kept its old name alive as a second node and a hunt on the loaded graph disagreed with `graph-hunt-csv` (DFIR Madness: the DC split into `CITADEL-DC01` and `WIN-E0PO207ERMD`). IPs the test cannot tie to a name stay as their own node; `merge-*-nodes` is the manual way. `graph-hunt` on its side now drops a login from a machine to itself under its own folded IP, as the loaders do, so a hunt on a loaded graph and on the CSV see the same rows (DFIR Madness: 8 and 8).
- **Build:** polars is gone. The Windows and Winlogbeat parsers built a DataFrame only to write it as CSV; they now write the rows directly with the same quoting (`src/csv_out.rs`), byte-identical output on the EVTX sample sets, a build that no longer carries polars-plan's future-incompatibility warnings, and a Windows binary of 16 MB instead of 27.
- **Build:** quick-xml 0.20 -> 0.42 (the other crate flagged as incompatible with a future Rust). Attributes and text in the event structs use the `@name` / `$text` names of the new serde layer, and whitespace-only element text is trimmed as before, so `<Param2>` with a line break stays an empty field.
- **CI:** `functional.yml` runs the real pipeline on every push: it fetches two public EVTX sample sets, parses them and runs `graph-hunt-csv` on Linux, Windows and macOS (Apple Silicon natively and the Intel binary under Rosetta on the same runner), normalises the artifact paths and fails if any operating system produced a different timeline. `ci.yml` builds and tests on Linux, Windows and macOS with stable Rust on every push and pull request, and prints the future-incompatibility report, so a dependency that stops compiling on a new toolchain is caught before a tag is cut (the v1.1.0 release failed that way on `ethnum`).

## v1.1.0 — 2026-10-05

### The statistical graph-hunt

`graph-hunt` is no longer a scorer with hand-picked weights: every signal is a probability measured against the network's own baseline, and `--alpha` is the only number you choose. The same hunt runs on Neo4j, on Memgraph and straight from the timeline CSV (`graph-hunt-csv`), with Hopper's classes, causal paths, `--seed` reconstruction and an analyst `--report`. On the public Los Alamos set (21 M rows) the first 100 rows are 99 % red team and an incident-free period yields nothing. Around it: Linux session ends and `logon_id`, UAC triages, Sysmon Event 3, a JSON extractor for custom rules, images inside zips for `parse-massive`, and a long list of parser fixes validated on real EVTX.

- `parse-windows` / `parser-elastic` / `parse-cortex-evtx-forensics`: **4778 and 4779 carry logon_type 10.** Session reconnect / disconnect are Terminal Services events; the column was empty (Cortex gave them 3). Validated on the EVTX-to-MITRE-Attack samples.
- `parse-custom`: **`type: json` extractor**. A rule can now parse NDJSON logs (one JSON object per line) and pull scalar fields by dot-path, both flat (`EventID`, `TargetUserName`, `SourceIp` — the Mordor / nxlog / HELK / SIEM-export shape) and nested (`winlog.event_id`). This closes the JSON gap in the custom-parser framework and lets masstin ingest JSON event logs it could not before. Ships with a new library rule **`rules/json/mordor.yaml`** for the OTRF Security-Datasets (Sysmon Event 3 on lateral-movement ports, 4624/4625/4634/4647/4648/5140); validated end-to-end against real OTRF data.
- `parse-windows` / `parse-image` / `parse-massive`: **Sysmon Operational Event ID 3 (network connection)** is now parsed (Sysmon EVTX was ignored entirely before). The host running Sysmon is the local endpoint; `Initiated` decides direction (outbound local -> remote on the destination port, inbound remote -> local on the source port). Only connections whose service port is a lateral-movement one (22, 135, 139, 445, 1433, 3306, 3389, 5900, 5985, 5986) are kept — Sysmon logs every connection, so the port filter keeps the volume sane — and each becomes a `CONNECT` edge origin -> destination with the initiating process and protocol in `detail`. Loopback and self-connections are dropped. Other Sysmon events (process creation, named pipes, file, registry) stay out of scope: they are tool attribution, not lateral movement.
- `parse-massive`: **forensic images packed inside a zip** (E01 multi-segment, VMDK with its extents, dd/raw/img) are now processed. The massive walker finds every zip under the evidence dirs and, for the ones carrying image segments, checks free space, extracts the image set to a temp dir on the **archive's own drive** (never the system temp, which may be a nearly-full C:), feeds the images through the normal image pipeline and removes the temp dir afterwards. `parse-windows` / `parse-image` are unchanged — only the no-mercy `parse-massive` digs images out of archives; images that are `Stored` or `Deflate` are both handled (the extraction is to disk either way). A pre-flight free-space check skips an archive instead of filling the disk half-way.
- `parse-linux`: **syslog lines with ISO timestamps** (`2026-09-25T10:11:12.123456+02:00 host sshd[1]: ...`, rsyslog's `RSYSLOG_FileFormat`, the Debian 13 default) are parsed; they were dropped. The stamp's own offset is used, whole seconds kept.
- `parse-linux`: **`message repeated N times: [ ... ]`** (rsyslog) yields N events; it counted as one (N failed passwords became one failure).
- `parse-linux`: **December lines in the current, unrotated `secure` / `auth.log`** get the previous year: a line cannot be dated after the file was last written (same rule as the logrotate suffix, with a day of slack). They were stamped with the following year and sorted into the future.
- `parse-linux` (journald): **OpenSSH 9.8 and later** log each connection as `sshd-session`; those entries were ignored. Syslog files already matched `sshd-session[pid]`.
- `load-neo4j` / `load-memgraph`: **CSV fields are read with quotes honoured.** The loaders split every line on raw commas, so an account name or detail text containing a comma (which an attacker can choose) shifted the columns and could put a chosen value in the origin of an edge; `graph-hunt-csv` already read quotes. A comma inside a field becomes `_`.
- `load-neo4j` / `load-memgraph`: **IPv6 addresses** are kept whole (`fe80::1%eth0`, `[2001:db8::1]`); the address extractor stopped at the first letter. Host names made of hex digits (`CAFE`, `BADC0DE`) or of digits are no longer taken for addresses. `localhost` counts as a local source like `127.0.0.1`. The Memgraph loader skips a short (truncated) row instead of aborting.
- `graph-hunt`: the run prints the weekday / weekend split of the null and of the window ("Day kinds: ..."). Matching each window day's null to the days of its kind was measured and dropped (docs: it halves the null and raises the p floor enough to lose findings without changing the order).
- `graph-hunt` / `graph-hunt-neo4j` / `graph-hunt-csv`: **the owner of an account is read from the logs.** A credential switch now weighs the account's *home share*: of its earlier successful login-days, the share that came from its most frequent origin (1 = it always came from one machine, near 0 = a service or administrator account used from everywhere). Four logins with an account that lives on one other machine weigh 4; four with an account used from 900 machines weigh almost nothing (before, both counted 4). The explanation names the home: "the account belongs elsewhere: 100% of its earlier login-days came from C8198 (7 day(s))". No inventory needed.
- `graph-hunt` / `graph-hunt-neo4j` / `graph-hunt-csv`: **the null skips the shallow days.** A baseline day enters the null only when at least half of the baseline days with data lie before it: with "reference = every earlier day" the first days see almost everything as new (on LANL the second day contributed 19,824 new connections, the fifth 2,047) and were filling the null with novelty that was unseen rather than unusual. On a case with years of wtmp history nothing changes; on LANL's 7-day baseline the null keeps the last three days. LANL: 56 -> 204 significant (185 red team, 42 % of the 444 instead of 13 %; the other 19 are one unlabelled machine that failed on 47 hosts and logged in with 7 accounts new to it), first 100 rows 99 % red team, 0 significant on the incident-free period. Measured separately, the null rule accounts for the whole gain (203 significant without the owner weight); the owner weight changes the order only and adds the home to the explanation.
- **LANL benchmark** (README, "Detection quality"): 21.3 M rows of the public Los Alamos set, cutoff day 7: 56 significant connections, all red team; first 100 rows 100 % red team, first benign row at rank 168, 60 % of the red-team connections within the first 500 rows of 465 k; 0 significant on an incident-free period. Converter and harness in `viconppt/graph-hunt-tests` (outside the repo).
- `graph-hunt`: **reference = the past only, every day alike.** A fact is new on a day when it occurred on no earlier day, in the baseline or in the window (earlier window days count too). The previous rule, "the past with the window's gap", needed a baseline longer than the window and on LANL (7 baseline days, 9 window days) left no null at all. The origin stories and the campaign / seed history checks count baseline days as days before the cutoff. Peak memory of `graph-hunt-csv` on 21 M rows: 6.9 GB (Browser snippets are now built when the CSV is written, not kept per row; CSV fields are borrowed, not copied).
- **`graph-hunt-csv`**: the same hunt straight from masstin timeline CSVs (`-f`), no graph database. The rows become the corpus the graph pull produces, with the loader's conventions (short upper-case host names unless two FQDNs share one, local sources dropped, accounts as relationship types, one coverage span per log file per destination); pre-auth touches and unnamed failures are aggregated per day. On a 10 M-row timeline it gives the same significant connections and the same order as the Neo4j run, in 5 minutes and 566 MB, from the 2 GB CSV. All options apply (`--report`, `--seed`, `--sigma`, `--end-time`).
- `--report`: each origin now ends with **"Could be benign if"** and **"To rule that out"** (fixed text per class: shared jump hosts, orchestration accounts pointed at new hosts, new accounts, scanners and probes...) and **"Events to pull"** (the raw Linux or Windows events that settle it, chosen by the log families that recorded the origin). Text only: no number changes.
- `graph-hunt` / `graph-hunt-neo4j` **CSV: three new columns** after `logs`: `signature` (the Hopper class, one value to filter on), `evidence` (every reason with its baseline count) and `chain` (place in the `--seed` reconstruction). `why_unusual` keeps the reasons in short phrases without numbers. Layout: `rank, significant, p_value, q_value, day, first_seen_utc, last_seen_utc, origin, destination, account, result, events, logs, signature, why_unusual, evidence, chain, campaign, cypher_snippet`.
- `graph-hunt` / `graph-hunt-neo4j`: **causal paths and the seed chain use recorded session ends.** A login B→C is caused by a session open on B at that moment (entered before, LOGOFF not yet written), so a cause can have entered on an earlier day and a session closed hours before is no longer a candidate; without a LOGOFF the end of the UTC day is assumed, as before.
- `graph-hunt` / `graph-hunt-neo4j`: **`--sigma` corroboration with Hayabusa / Chainsaw.** Their JSON or JSONL output (files or directories, comma-separated) is read once; a hit on a machine while a login session is open on it (from the login to its LOGOFF, or the end of the day) is the coordinate `sigma` (distinct rules that fired) of that connection, measured against the baseline like every other, and the explanation names the rules, times and levels. masstin does not detect PsExec, WMI or service installs itself; it joins what those tools found to the login that made it possible.
- `graph-hunt` / `graph-hunt-neo4j`: **`--seed` reconstruction.** Given known-bad hosts, IPs or accounts (comma-separated), the report opens with the chain: every window login by a seed, then every login leaving the entered machine while that session is open (LOGOFF when recorded, else the end of the UTC day) that is a new connection or uses an account the chain already used, with certainty 1 / (sessions open on the machine at that moment); one level back (what was open on a seed machine when it first acted); failed attempts and unauthenticated touches from the chain machines; and two Cypher queries: the chain as a virtual graph (APOC; real-edge match on Memgraph) and everything between the chain machines in that time span. Requires `--report`. A seed that existed in the baseline starts the chain only with its new connections (its habitual logins are counted and listed, not followed); a never-seen seed with everything. `host:account` seeds both at once; `--seed-from` / `--seed-to` bound the logins that start the chain.
- `load-neo4j` / `load-memgraph`: edges carry `logon_id` (Windows LogonId, Linux sshd pid) so a login and its LOGOFF can be paired in the graph.
- `parse-linux`: **session ends as `LOGOFF` rows and `logon_id` filled.** Every closed SSH session yields one LOGOFF row (event_id `LOGOUT`) with the user and source of the login it closes, from wtmp (`DEAD_PROCESS` paired with the login of the same terminal), sshd's pam `session closed` line (paired with the `Accepted` line by pid; `Disconnected from user` lines used only for files without pam session lines), journald (same) and auditd `USER_END` (same `ses=` as the login, the last one per session kept; dropped when the sshd log already has the close, paired by pid). `logon_id` now carries the sshd process id on every Linux row that has one (`sshd[pid]`, journald `_PID`, auditd `pid=`, wtmp `ut_pid`), the same on a login and on its LOGOFF, so sessions can be paired and their duration measured. No other row changes.
- **`graph-hunt` / `graph-hunt-neo4j`: Hopper's signature, causal paths, analyst report** ([design](docs/graph-hunt-statistics.md)).
  - each connection is classed by the two properties Hopper (Ho et al., USENIX Security 2021) found in lateral movement: a **credential switch** (account owned by other origins, never used by this one) and a **new access** (destination new for the origin or the account). The class is the first clause of `why_unusual` and orders the rows within the significant set; p-values are untouched. New origin-day coordinate `credential-switch`.
  - `chain-motif` replaced by **`causal-path`**: a login B→C is caused by one of the logins A→B of the same UTC day, with certainty 1 / #candidates; the path counts when the credential changed at B and the causal account had never reached C. The connection row explains the path in words.
  - connections of an **origin with no history** are evaluated even on destinations without comparable coverage (they were listed as *not evaluated*).
  - **`--report path.md`**: one story per origin with a significant connection: baseline presence, chronological phases, reasons with baseline counts, account owners, causal paths, campaign, log families, Browser query.
  - `LOGOFF` rows are no longer counted as logins; the centrality clause prints only the component that changed.
  - **Statistical review fixes** ([assumptions and limits](docs/graph-hunt-statistics.md#assumptions-limits-and-what-the-numbers-mean)): past-only reference with the window's gap (a fact is new on the first day it appears, for baseline and window days alike; the former leave-one-day-out made a repeating fact never new in the baseline and new on every window day); the Benjamini-Hochberg family holds the new connections only (habitual ones have p = 1 and cost no power); the run prints the smallest reachable p; an empty null gives p = 1 instead of a crash; account names with non-ASCII characters no longer crash the uid check; a refused attempt is not a "use" of an account by an origin (a spray that started before the cutoff and succeeds in the window is a credential switch); origins without history are judged with every destination-side fact switched off on uncovered destinations; PageRank iterated to stationarity with a data-derived zero threshold; the causal-path coordinate counts connections, not sessions; the panel ends on the last covered baseline day and an empty panel stops the run; an IP and its own unresolved host name are never paired as a campaign; explanations state on how many baseline days each fact occurred.
  - **IP ↔ host name resolution is a binomial test** over the IP's logins (trials) and the seconds where exactly that name was recorded too (votes), with the name's own rate as chance probability; BH across (IP, name) candidates, one unambiguous name per IP. The former product of per-vote probabilities was a likelihood, not a tail probability, and could fold two busy machines sharing an account.
- **`graph-hunt` / `graph-hunt-neo4j` rewritten as a statistical engine** ([design](docs/graph-hunt-statistics.md)). Every hand-picked weight, window, minimum and threshold is gone; each signal is an empirical probability measured against the network's own baseline, and `--alpha` (false discovery rate, default 0.05) is the only chosen number.
  - leave-one-day-out reference (a fact is new on a baseline day if it occurs on no other baseline day), UTC day as unit;
  - coverage from log-file time spans written by the loaders (`cov_ok` / `cov_fail` on host nodes); counts compared on a panel of continuously covered destinations, start day chosen to maximise panel size x baseline days; window logins elsewhere reported as *not evaluable*;
  - one joint test per origin-day over ten signals (first-time destinations, new accounts, never-seen account/destination pairs, Louvain community crossings, failed destinations, SSH pre-auth touches, probe-then-success, no history, rarest logon type, fastest chain), calibrated empirically (conformal p-value, valid under any dependence); host-day joint test on PageRank / betweenness change;
  - Simes per machine, Benjamini-Hochberg across machines; campaign rows via exact hypergeometric overlap test;
  - IP and host name reported as one machine when same-login co-occurrence is unanimous and a chance coincidence is statistically ruled out;
  - PageRank, betweenness (Brandes) and Louvain computed in memory: **GDS / MAGE no longer required**; grouped graphs are refused (no per-event times);
  - new CSV layout: `section, rank, machine, machine_p, machine_q, significant, detector, role, p_value, day, hosts, account, events, time_window, summary, cypher_snippet`.
- `parse-linux`: **SSH pre-authentication touches** ("Did not receive identification string", "Bad protocol version identification", closed/reset/disconnect `[preauth]`) are written as CONNECT rows, event_id `SSH_PREAUTH`, user empty.
- `parse-linux`: **auditd paired with sshd by process id** (same host, pid, source and outcome, sshd line from a log file that covers the audit record, one-to-one) instead of a +-1 s same-account match; successful audit connections collapsed by `(pid, ses)` across rotated files instead of a 600 s window; USER_AUTH fallback limited to `op=success` / `op=PAM:authentication`.
- `load-neo4j` / `load-memgraph`: `resolved_name` kept when unanimous and significant against chance coincidence (Poisson model, Benjamini-Hochberg across IPs; new `resolved_p`), replacing the fixed minimum of two votes; destination nodes get `cov_ok` / `cov_fail` log-file spans; `--alpha` applies.

- `parse-linux`: **UAC (Unix-like Artifacts Collector) triage detection**, alongside KAPE / Velociraptor / Cortex XDR. Detected by `uac.log` + `[root]/` layout or by the `uac-<host>-<os>-<timestamp>` filename; hostname from the filename, `[root]/etc/hostname`, `/etc/sysconfig/network`, `uac.log`, `/etc/hosts` or the syslog header when UAC was run against a mounted image (`unknown`).
- `parse-linux`: **tar / tar.gz / tgz archives** are now walked (streamed, selective extraction of log files only), including nested combinations (zip → tar.gz, tar.gz → tar.gz). Archives copied off the victim filesystem under `[root]/` are never recursed into.
- `parse-linux`: rotated `wtmp-YYYYMMDD` / `btmp-YYYYMMDD[.gz]` are parsed; the logrotate suffix drives the year of RFC3164 timestamps in rotated `secure` / `messages` / `auth.log` files.
- `parse-linux`: `log_filename` shows `<archive>:<path inside>` for artifacts that came out of an archive instead of a temp path; `/etc/hosts` no longer yields `localhost.localdomain` as a hostname.
- ZIP extraction streams entries to disk instead of loading the whole archive into memory.
- `parse-linux`: **RFC3164 timestamps converted from the host's local zone to UTC** (zone from `/etc/timezone`, `/etc/sysconfig/clock`, `/etc/localtime` symlink or TZif contents, or live `timedatectl`). Previously syslog lines were taken as UTC and sat hours away from wtmp / audit / journald for the same login.
- `parse-linux`: sshd regexes generalised — any `Accepted <method>`, `Failed <method>` **including `invalid user`** (previously unmatched), and `not allowed because` policy denials; method recorded in `detail`. `Failed none` probes ignored. `pam_unix(sshd:auth)` failures demoted to a fallback (false failed logons on SSSD hosts).
- `parse-linux`: wtmp/utmp/secure keep sources that are hostnames, not only IPs (`UseDNS yes` estates lost >99% of wtmp). Boot / runlevel utmp records dropped.
- `parse-linux`: **lastlog parsed** (last login per account, uid resolved via the collected `/etc/passwd`).
- `parse-linux`: journald ⟷ rsyslog duplicates removed across files; truncated archives reported with a warning.
- `parse-linux`: audit.log now keeps `USER_LOGIN` only (one record per SSH connection; `USER_AUTH` PAM/key stages were producing 3–4 rows per login and are used only as a fallback), collapses the duplicate `USER_LOGIN` pairs sshd writes per pid, resolves the `id=`/`auid=` uid of successful logins through the collected `/etc/passwd` (previously an empty user → `NO_USER` in the graph) and tags `acct="(unknown)"` failures as `audit invalid-user` in `detail`. `logon_type` is `SSH` on every Linux row.
- `load-neo4j`: **fix silent edge loss** — host nodes were merged lazily every 256 names while edge batches went out every 5000 rows; batches whose origin node did not exist yet were dropped by Cypher without an error while the summary still counted them (a 76k-row timeline came out as 21k edges). Nodes are now flushed before every edge batch and the summary reports the server-side count. Edges carry `event_type` and `event_id` so success and failure can be told apart in the graph.
- `graph-hunt` / `graph-hunt-neo4j`: findings CSV is aggregated per (detector, host, origin/user/destination pattern) with an `events` column and a first..last `time_window`, instead of one row per edge (a 9000-attempt brute force is one row, not 9000).
- `graph-hunt` / `graph-hunt-neo4j` detector rework:
  - structural detectors, the baseline and the GDS projections use **authenticated logins with a real account only**; failed / unauthenticated attempts go to the new `failed-sweep` detector. Fixes PageRank / betweenness "spikes" caused by monitoring probes.

  - **corroboration**: +0.25 per other detector on the same origin; new `origin`, `corroboration` columns.
  - community-bridge only for origins with authenticated baseline history; Louvain on a login-count-weighted projection.
  - novel-edge / community-bridge aggregate per (origin, account, destination) in Cypher (events + first..last).
  - lastlog counts as proof a relationship existed, not as frequency.
  - Browser-ready snippets on Neo4j (APOC virtual graph — no "connect result nodes" explosion).
  - coverage warning per log source (needs `log_source` on edges).
  - shared code in `graph_hunt_common` for both backends.
- `load-neo4j` / `load-memgraph`: `count` stored as an integer (was a string); edges carry `event_type`, `event_id`, `log_source`; IP nodes annotated with `resolved_name` from unanimous same-login IP/name pairs (not merged); **grouped mode keyed by source and outcome** — two origins using the same account on the same host used to collapse into one edge, and refused attempts merged with successes.

### What's in 1.0

**Windows parsing**

- `parse-windows`: EVTX from directories, files, and recursive zip trees. Dispatch by `Provider.Name`, so archived and renamed logs (`Security-YYYY-MM-DD-HH-MM-SS.evtx`, operator-renamed copies, third-party triage extracts) all parse correctly.
- `parse-image`: forensic disk images (E01, VMDK in every variant, raw/dd, img) with per-partition OS auto-detection, NTFS walker, VSS recovery, UAL, Scheduled Tasks, MountPoints2.
- `parse-massive`: everything above plus KAPE / Velociraptor / Cortex XDR triage detection and loose-artifact promotion. One command for mixed evidence piles.
- `carve-image`: Tier 1 chunk recovery + Tier 2 orphan record detection from unallocated space, hardened against the upstream `evtx` crate's pathological BinXML allocations via subprocess isolation.

**Linux parsing**

- `parse-linux`: auth.log, secure, messages, audit.log, utmp, wtmp, btmp, lastlog.
- `parse-image` on ext4: the same plus a pure-Rust systemd-journald binary log reader, for modern systems where the text logs are empty and all authentication events live in the journal.

**Third-party integrations**

- `parse-cortex` and `parse-cortex-evtx-forensics`: Cortex XDR API queries for network connections and forensic EVTX collections.
- `parser-elastic`: Winlogbeat JSON dumps exported from Elasticsearch.
- `parse-custom`: any VPN / firewall / proxy / web app log via YAML rule files. Ships with 8 pre-built rules for Palo Alto GlobalProtect, Cisco AnyConnect, Fortinet SSL-VPN, OpenVPN, Palo Alto traffic logs, Cisco ASA, Fortinet FortiGate, and Squid.

**Graph output**

- `load-neo4j` / `load-memgraph`: grouped (topology) or ungrouped (temporal path hunting) loading modes.
- `merge-neo4j-nodes` / `merge-memgraph-nodes`: vanilla Cypher node fusion, no APOC / MAGE required.

**Binaries**

Zero runtime dependencies on every platform:

- Windows x86_64
- Linux x86_64
- macOS Apple Silicon (arm64) — native
- macOS Intel (x86_64) — native

**Filtering**

`--ignore-local`, `--exclude-users`, `--exclude-hosts`, `--exclude-ips` (CIDR and `@file.txt` syntax) for cutting noise out of long timelines.
