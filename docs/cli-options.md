# All command-line options

Every flag, grouped by the actions that use it. Back to the [README](../README.md).


| Option | Description |
|--------|-------------|
| `-a, --action` | `parse` (every kind of evidence in one pass, [Parsing →](parsing.md#-a-parse-one-action-for-every-kind-of-evidence)) \| `parse-windows` \| `parse-linux` \| `parse-mac` \| `parse-image` \| `parse-massive` \| `carve-image` \| `parser-elastic` \| `parse-cortex` \| `parse-cortex-evtx-forensics` \| `parse-custom` \| `merge` \| `load-neo4j` \| `load-memgraph` \| `merge-neo4j-nodes` \| `merge-memgraph-nodes` \| `graph-hunt` \| `graph-hunt-neo4j` \| `graph-hunt-csv` \| `host-map` (whose each address of a timeline is, [the host map](graph-hunt.md#whose-address-is-it-the-host-map)) \| `view`. Aliases: `hosts` (host-map), `auto` (parse), `parse-macos` (parse-mac), `parse-image-windows` / `parse-image-linux` (parse-image), `load` (load-neo4j) |
| `-d, --directory` | Directories to process — also accepts drive letters (`D:`) for mounted volumes (repeatable) |
| `-f, --file` | Individual files (repeatable): EVTX, `.mdb`, E01, VMDK, VHD/VHDX, dd/raw for the Windows and image actions; Windows events as JSON (Winlogbeat, evtx_dump, Velociraptor, flat) for `parser-elastic`; `.logarchive` or `log show` JSON for `parse-mac`; any text or JSON log for `parse-custom`; masstin CSVs for `merge`, the loaders, `graph-hunt-csv` and `view` |
| `-o, --output` | Output file path. Without it the timeline goes to stdout |
| `--database` | Graph database URL (e.g., `localhost:7687`) |
| `-u, --user` | Database user. Required by `load-neo4j` and `merge-neo4j-nodes`; `graph-hunt-neo4j` defaults to `neo4j`; optional (empty) on the Memgraph actions |
| `--db` | Target database name on the graph server (default `neo4j` for Neo4j actions, `memgraph` for Memgraph). Useful in multi-database Neo4j 5.x/2026.x setups. |
| `--cortex-url` | Cortex XDR API base URL, starting with `https://api-`. The API key and its numeric id are asked on the console, or read from `CORTEX_API_KEY` and `CORTEX_API_KEY_ID` when both are set (a script, or masstin's window, never puts the key on a command line). Standard and Advanced keys both work: masstin asks the tenant which kind it is (`CORTEX_API_KEY_TYPE=standard\|advanced` skips the question) |
| `--cortex-sources` | `parse-cortex`: the tenant's sources to read, a comma-separated list of `network` (the endpoints' network connections), `eventlog` (the Windows event logs every agent sends: logons, logoffs, Kerberos, NTLM, shares) and `forensics` (the event logs the forensics add-on collected). Left out, or `all`: the three, merged into one timeline; a source the tenant does not have is said and left out. Without a time window: the last 7 days of the first two, the last year of the forensics |
| `--start-time` | Filter start: `"YYYY-MM-DD HH:MM:SS"`, UTC (Cortex actions, `merge`, `load-neo4j` / `load-memgraph`). Also read: a date alone (`2026-01-05`, its first second), `T` between date and time, no seconds, and a zone at the end (`+0200`, `-05:00`, `Z`), which is converted to UTC |
| `--end-time` | Filter end, in the same shapes (same scope as `--start-time`); a date alone is its last second, so the whole day is inside. For `graph-hunt*`, the end of the hunted window |
| `--ungrouped` | For `load-neo4j` / `load-memgraph`: emit one edge per CSV row instead of grouping |
| `--old-node` | For `merge-neo4j-nodes` / `merge-memgraph-nodes`: name of the `:host` node to remove (its edges are transferred to `--new-node`) |
| `--new-node` | For `merge-neo4j-nodes` / `merge-memgraph-nodes`: name of the `:host` node that survives the merge |
| `--filter-cortex-ip` | Filter by IP in Cortex queries |
| `--admin-ports` | `parse-cortex`: widen network port list to full admin set (22, 135, 139, 445, 1433, 3306, 3389, 5900, 5985, 5986). Default is RDP/SMB/SSH + WinRM. |
| `--cortex-event-ids` | `parse-cortex-evtx-forensics`: comma-separated override of the default Windows Event ID set |
| `--cortex-min-window-secs` | Auto-pagination floor for both Cortex actions when a time window saturates the API 1M cap (default 300) |
| `--cortex-max-passes` | Hard cap on auto-pagination passes for both Cortex actions (default 200) |
| `--all-volumes` | Scan all NTFS volumes on the system (parse-image, requires admin) |
| `--overwrite` | Overwrite the output file if it exists. Asked for by every action that writes a timeline (the parsers, `merge`, `carve-image`, the Cortex actions): without it an existing `-o` is an error, said before anything is read. `-o` is never one of the files being read (the timeline would replace the evidence), unless that file is a masstin timeline being merged into |
| `--threads N` | Threads for parsing (the EVTX chunks, the records into rows, the sort and the writing). Left out, masstin measures the machine: the pool is all its cores but one (a single thread on a machine of one to three cores), and what is put to work at each moment is what is idle right then, less one core for the system, measured again as the run goes. `1` runs exactly as masstin ran with no parallelism; `N` fixes the figure whatever the load. The process runs below normal priority either way (`MASSTIN_PRIORITY=normal` keeps it normal, for a server where masstin is the job). `MASSTIN_THREADS` does the same |
| `--parallel-images N` | For `parse-image` / `parse-massive`: forensic images extracted at once. Left out, masstin finds the figure by measuring: it starts with one reader on a spinning disk and two anywhere else, doubles the readers while the bytes a second coming off the images keep growing, keeps the last size that helped when a doubling brings nothing, halves them when the rate falls; the idle cores and the free memory (half a gigabyte a reader) are the ceiling. `N` fixes the figure. `MASSTIN_PARALLEL_IMAGES` does the same |
| `--debug` | Print debug information (also keeps rejected synthetic EVTX in `carve-image` and, when `-o` is given, a sample of rejected lines in `parse-custom`) |
| `--silent` | Suppress all output for automation (Velociraptor, SOAR) |
| `--rules PATH` | `parse-custom`: YAML rule file or directory of rules (see [`rules/`](../rules/)). `parse`: the files given one by one that masstin does not recognise (VPN, firewall, proxy logs) are read with these rules, merged into the same timeline |
| `--carve` | `parse`: the disk images found are also carved for the EVTX records of deleted or overwritten logs (`carve-image`); the carved events the live logs already hold are dropped, the rest merged into the same timeline. Slow: every byte is read |
| `--dry-run` | `parse-custom`: show first matches and rejected lines, write no CSV. With any filter flag on a parser action: print the filter stats and write only the CSV header |
| `--ignore-local`, `--exclude-users`, `--exclude-hosts`, `--exclude-ips` | Noise filtering on every parser action and `merge` (see [Noise filtering](parsing.md#noise-filtering---ignore-local-and---exclude-)) |
| `--carve-unalloc` | `carve-image`: planned unallocated-only scan; not implemented yet, the whole image is scanned and a warning says so |
| `--skip-offsets LIST` | `carve-image`: comma-separated hex offsets to skip (32 MB window each) on a pathological E01 |
| `--investigation-from "YYYY-MM-DD HH:MM:SS"` | `graph-hunt*`: cutoff (UTC); a date alone is read too. Days before it are the baseline, the rest the window. Required. A hunt that cannot be computed (no connection on or after the cutoff, fewer than two days of baseline before it) writes nothing, says from when to when the timeline runs, and ends with an error |
| `--alpha` | `graph-hunt*` and loaders: false discovery rate for Benjamini-Hochberg (default 0.05), the only chosen number |
| `--only-detectors` / `--skip-detectors` | `graph-hunt*`: comma-separated signal names to run exclusively or to drop (mutually exclusive) |
| `--report FILE.md` | `graph-hunt*`: also write the analyst report, one story per origin with a significant connection |
| `--no-annotate` | `graph-hunt-csv`: leave the timeline untouched. By default every `-f` timeline is rewritten in place with `hunt`, `hunt_score` and `hunt_why` filled (`verdict` and `notes` kept) |
| `--if-hunted overwrite\|keep\|new` | `graph-hunt-csv`: what to do with a `-f` timeline that already carries a hunt. `overwrite` (default): this hunt replaces the one it had, in place. `keep`: that timeline is left as it is (it still counts in the statistics). `new`: the timeline with this hunt is written to a new file next to it, `<name>.hunt-<date of --investigation-from>.csv`, and the one given keeps its hunt; the line `New timeline: OLD -> NEW` names it. In every case masstin says the timeline was hunted before and with what (see [the hunt record](csv-format.md)) |
| `--merge-hosts strict\|standard\|broad` | `graph-hunt-csv`: read an address as the host it is, for the whole hunt, when the timelines themselves say whose it is. `strict`: what a machine says of itself (the addresses in its SYSTEM hive) or of its domain controller (Group Policy 5308), both kept in `<name>.masstin` when the evidence was parsed. `standard`: also the machine's own account (`NAME$`) authenticated from the address. `broad`: also the name the client gave in the event, and the same-login test. An address stays as it is when the evidence disagrees (several names at it, or its host at two addresses in the same period). The timeline's columns are not changed; `-a host-map` shows the table first. See [the host map](graph-hunt.md#whose-address-is-it-the-host-map) |
| `--merge-hosts-skip ADDRESS,ADDRESS` | With `--merge-hosts`: addresses to leave as they are whatever the evidence says |
| `--carry-marks FILE.csv` | `merge` / `graph-hunt-csv`: copy `verdict` and `notes` from an earlier timeline onto the rows with the same 14 event columns |
| `--focus HOST` | `view`: open on the neighbourhood of this host (name or IP, `*` wildcards) instead of the hunt's findings; `--start-time` / `--end-time` bound the window |
| `--rows LINE,LINE` | `view`: open on exactly these rows as a graph of their own, one edge per row (ungrouped) and only the hosts they name. Rows by their line in the file (the header is line 1, the first row 2); `N:LINE` is a line of the N-th `-f`. How another program hands a selection of rows to masstin's graph |
| `--seed LIST` | `graph-hunt*`: known-bad hosts, IPs, accounts or `host:account`; the report opens with the reconstructed chain. Requires `--report` |
| `--seed-from` / `--seed-to` | `graph-hunt*`: only logins in this UTC range start the seed chain |
| `--sigma LIST` | `graph-hunt*`: Hayabusa / Chainsaw JSON or JSONL files or directories; a rule that fired during a login session becomes one more measured signal |
